### 3.1 Telegram approval gate

Signal fires → Telegram message with Approve/Reject buttons → owner taps →
`repository_dispatch` fires the (not-yet-built) `activate-strategy.yml`.
Scoped and decided; contracts below are ready to implement.

**Design decisions already locked** (do not re-litigate):

- **Intent-level, not signal-level.** A raw signal carries no personality,
  strike or lots — those only exist after `personality-router.ts` runs its
  5-stage filter. The gate hooks the `passingIntents[]` array, filtered to one
  configured execution personality.
- **The internal paper-trade simulator is unaffected.** `personality-router`
  opens simulated trades for every passing personality unconditionally
  (`personality-router.ts:539-542`). Rejecting or expiring an approval only
  means "do not also fire this on real AlgoTest".
- **Webhook, not long-polling.** `apps/server` is already a public HTTPS
  service with a webhook precedent (`routes/payment.ts`).
- **Explicit Reject button**, not expiry-as-implicit-reject — Phase 5 wants
  approve/reject as a labelled dataset.
- **`dispatch_failed` is a distinct state** from `approved`, surfaced in the
  Telegram message, so a GitHub API failure is never silent.
- **FK the signal, snapshot the params.** `straddle_signals` already stores the
  signal immutably, so reference it. The strategy params are mutable config, so
  snapshot them as JSON on the row — same reasoning as
  `option-backtesting`'s `strategy_yaml` registry column.
- **Use `recoverPending()` + `streamConsume()`** (the `position-monitor.ts`
  pattern), *not* `personality-router.ts`'s hand-rolled read loop — see 3.5.4.

### 3.9 Category-momentum backtest layer — built and analysed; doesn't beat plain ETFs except in one category

`packages/momentum-backtesting/src/momentum_backtesting/categories/` (built
2026-09-28): the existing sector/thematic ETF-rotation engine (unchanged)
ranks categories (Nifty Bank, PSU Bank, IT, etc.) as it does today; when a
category is investable, an *inner* backtest substitutes the top-K individual
stocks currently tagged to that category (instead of the ETF), rotating them
on their own tighter threshold. `mbt categories fetch|resolve|backtest`.
16/16 of `universe.csv`'s Sector/Thematic categories now have working NSE
constituent-list sources (4 needed their real, inconsistently-named slug
tracked down by hand). Zero `engine.py` changes — both the inner and outer
backtests are ordinary, unmodified calls to `run_backtest`. 392 tests pass,
ruff clean.

**Two real bugs found and fixed during verification**, both the same
underlying mechanism (a held position's price column going NaN corrupts the
whole portfolio total, permanently) but triggered two different ways: (1) a
forward-filled "zombie" price segment (kept flat, not NaN, specifically to
stop that corruption) was staying buy-eligible forever and got freshly
bought 10x in one real backtest before the fix; (2) a plain symbol rename
with no detectable price event at all (IDFCBANK → IDFCFIRSTB, 2019-01-16)
hit the *same* corruption a different way, since it isn't a "detected
event" the first fix's logic covered — generalised the fix to catch any
column whose real data simply runs out, event or not. `compose.py`'s
membership gate now tracks per-segment liveness from both sources.

**Real-data analysis (2026-09-28, full 2017–2026 period, defaults: top-2,
inner exit-rank 8, narrow mode)** — the actual, decision-relevant finding:
substituting individual stocks for the sector ETF **does not generally beat
holding the plain ETF**. Baseline (no substitution): **+25.05% CAGR**. Ran
all 16 categories individually — only **Nifty Metal** showed a clear,
positive edge (**+27.02%, +1.98pp**); every other category was flat or
negative, several substantially so (Nifty India Defence: **-5.74pp**, the
worst). Substituting **all 16 categories at once**: **+15.66%, a -9.39pp
hit** — confirms blanket application actively hurts, the negative
categories dominate. Even hand-picking the 5 least-bad categories together
(Metal, CPSE, Auto, Capital Markets, Infrastructure) still nets **-0.75pp**
— the drag compounds across categories rather than netting out. Metal alone
is, so far, the only case worth pursuing further; parameter sensitivity
(top-K, exit-rank) wasn't re-checked against this corrected dataset yet — an
earlier pass (before the second bug fix) looked promising for Nifty IT
across several parameter combos, but that used incomplete 2023–2024-only
membership data and is superseded by the corrected 16-category run above,
where IT is negative.
